# Какие-то скрипты для флиппера

Для себя я решаю только две проблемы: дедупликация и каталогизация. Особенно актуально, когда в интернетах натыкаюсь на очередную сборку всего по чуть-чуть для флиппера, уходит много времени чтобы понять что у меня есть, а чего нет. Я знаю, что есть утилиты для поиска дупликатов, типа fdupes(я ей пользовался), но они не понимают файлы, в которых несколько сигналов, т.е. для них это разные файлы, хотя сигнал из файла А, может содержаться в файле Б. Или, к примеру, в файле есть лишний комментарий - сигналы похожие, но с точки зрения поиска одинаковых - они разные по содержимому.

Моя первоначальная цель - запустить ряд скритов на какой-то каталог, они сами соберут в нем нужные сигнатуры и дополнят базу недостающим, а после загенерят мне новые файлы только с уникальными сигнатурами, без стопитцот копий. Пока я разделяю запуски на файлы, позже соберу под один запуск.


## iButton

### ibtn_parser.py 

Cобирает базу iButton ключей по указанной директории. Откидывает дубли и некорректные(определяется по ряду признаков) ключи. Можно натравливать на разные директории, он только дополняет каждый раз базу. При заполенной базе, сами файлы ключей не нужны. 

Скрипт конвертирует ключи из 1ю версии во 2ю, но не все. Нормально могут пройти: Cyfral, Metakom, DS1990, DS1420, Dallas - у них ничего не меняется между версиями. Точно не пройдут: DS1992, DS1971, DS1996, т.к. у них появляются во 2й версии поля SRAM и EEPROM, которые просто неоткуда брать.


### ibtn_dump.py 

Генерит списки файлов, делая подкаталоги из протоколов. Так же делает списки для ibtnfuzzer

## RFID

### rfid_parser.py

Собирает базу RFID из указанной директории. Откидывает дубли. Можно натравливать на разные директории, он только дополняет каждый раз базу. При заполенной базе, сами файлы ключей не нужны. 

### rfid_dump.py 

Генерит списки файлов, делая подкаталоги из протоколов.
